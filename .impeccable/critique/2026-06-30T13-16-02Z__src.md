## Anti-Patterns Verdict

**LLM assessment:** Mostly human-crafted. The app shows deliberate decisions (tonal layering, single typeface, gradient-from-artwork). The eyebrow on StatCard (`text-xs font-medium uppercase tracking-wide` on labels) is the clearest AI-template residue. The glass effect on TitleBar (beyond the player bar) is a minor DESIGN.md deviation.

**Deterministic scan:** 8 findings across 6 files. Key signals:
- 2x `ai-color-palette`: `from-violet-500` on card-item.tsx and playlist-hero.tsx — likely false positives since violet is the deliberate brand accent via profile theme
- 1x `layout-transition`: `transition: height` on songs-page.tsx — real performance concern
- 2x `design-system-color`: `#6b7280` and `#3b82f6` raw hex values not in token system — real drift
- 1x `design-system-radius`: `5px` outside DESIGN.md scale — borderline, between sm(6px) and md(8px) in actual code
- 2x likely false positives (violet accent and Instrument Sans font are documented in DESIGN.md)

## What's Working

1. **Dynamic background gradient from album art.** Signature feature executed with restraint. Transparent when idle, blooms on playback, uses mask-image fade. The color space conversion (HSL ↔ OKLCH) is thoughtful.

2. **Tonal layering over shadows.** The elevation system uses lightness steps, not box-shadow. Rare and mature. The zero-chroma neutral ramp is on-brand.

3. **Comprehensive skeleton/empty states.** Every page has tailored loading (HomeSkeleton, AlbumsSkeleton, DetailSkeleton) and empty states (icon + text + action). Real product thinking.

## Priority Issues

### P0: No keyboard shortcuts for a power-user app
- **What:** No spacebar play/pause, no arrows for seek/skip, no `Ctrl+F` search, no `?` shortcut overlay.
- **Why it matters:** Target user is "tech-literate audiophile" — exactly the user who expects keyboard shortcuts. Flexibility/Efficiency scored 1/4.
- **Fix:** space → play/pause, left/right → seek, up/down → volume, `Ctrl+K` → search (likely already partially via cmdk), `?` → shortcut reference overlay.
- **Detector correlation:** Not flagged by detector (semantic analysis gap).
- **Command:** `/impeccable animate shortcuts`

### P1: Icon-only sidebar with 1000ms tooltip delay
- **What:** 8 nav icons with no labels. Tooltip delay is 1000ms (Radix default).
- **Why it matters:** Recognition/Recall scored 2/4. Users must hover-wait or guess. Icons like `Import` (folder icon) are ambiguous.
- **Fix:** Reduce tooltip delay to 500ms. Consider showing labels on hover-expand or a sidebar-toggle.
- **Detector correlation:** Not flagged; detector doesn't check tooltip timing.
- **Command:** `/impeccable distill sidebar`

### P1: Inconsistent back button icons
- **What:** Album detail uses `ChevronLeft`, Artist detail uses `ArrowLeft`. Same pattern, different icon.
- **Why it matters:** Breaks muscle memory. Consistency scored 2/4.
- **Fix:** Standardize on one icon across all detail pages.
- **Detector correlation:** Semantic gap; not detected.
- **Command:** `/impeccable polish back-button`

### P2: Tiny uppercase tracked eyebrow in StatCard
- **What:** `text-xs font-medium uppercase tracking-wide` on stat labels. Banned by both PRODUCT.md and DESIGN.md.
- **Why it matters:** The one clear AI-template residue.
- **Fix:** Remove uppercase + tracking. Use `text-sm font-medium text-muted-foreground`.
- **Detector correlation:** Not flagged (detector doesn't check text-transform).
- **Command:** `/impeccable quieter StatCard`

### P2: Dead-end error states
- **What:** "Album not found" / "Artist not found" are dead-ends with no recovery action.
- **Why it matters:** Users who reach these states have no path forward. Error recovery scored 2/4.
- **Fix:** Add "Go back" button inside the empty state. The detail pages already have `goBack`.
- **Detector correlation:** Not flagged.
- **Command:** `/impeccable harden detail-pages`

### P2: Layout transition animating `height` (songs-page)
- **What:** `transition: height` on songs-page.tsx:233 — animates layout property, causes repaint thrash.
- **Why it matters:** Janky scrolling on songs list. Detector flagged this.
- **Fix:** Use `grid-template-rows` transition or `max-height` instead.
- **Detector correlation:** ✅ Caught by detector (`layout-transition`).
- **Command:** `/impeccable optimize songs-page`

### P2: Raw hex colors outside token system
- **What:** `#6b7280` in sidebar-section.tsx, `#3b82f6` in profile-store.ts — hard-coded values not using CSS vars.
- **Why it matters:** Token drift — these won't respect theme changes.
- **Fix:** Replace with `bg-muted-foreground` / `bg-primary` or equivalent token.
- **Detector correlation:** ✅ Caught by detector (`design-system-color`).
- **Command:** `/impeccable polish token-drift`

### P3: Home heading brightness filter
- **What:** `brightness-50 dark:brightness-100` on "Welcome Back" heading dims it in light mode for no reason.
- **Fix:** Remove brightness classes.
- **Command:** `/impeccable polish home-page`

## Persona Red Flags

### Alex (Power User)
- **No keyboard shortcuts anywhere.** App is unusable for this persona.
- **No bulk operations.** Must click each track individually.
- **No column header sorting.** Clicking "Title" or "Duration" in songs does nothing.
- **No "Play Next" / queue drag-and-drop.**

### Jordan (First-Timer)
- **Icon-only sidebar.** Doesn't know what the import button does. Must figure out navigation by trial-and-error.
- **"Who's listening?"** is warm but unexplained — what IS a profile?
- **1000ms tooltip delay.** Hovers, waits, moves on. Never learns labels.
- **"See all" links are `text-sm`** — easy to miss.

### Sam (Accessibility)
- **StatCard labels at `text-xs uppercase tracking-wide`** — small, tracked text likely fails WCAG 4.5:1 at that size.
- **Icon-only nav** fails "perceivable" principle at rest.
- **No `prefers-reduced-motion`** override for marquee/scroll animations.
- **Album detail scroll** — horizontal scroll container isn't keyboard-traversable.

### Riley (Stress Tester)
- **Empty states comprehensive** — passes this persona's main tests.
- **Large library** — virtualized lists everywhere. Strong.
- **Error recovery weak** — "not found" states are dead-ends.
- **Concurrent scan+playback** handled correctly. Strong.
